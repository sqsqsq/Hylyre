# Hylyre 0.5.2 截图输出验收

日期：2026-11-10。范围为 `fix-screenshot-format-consistency`，已[归档提案](../../openspec/changes/archive/2026-11-10-fix-screenshot-format-consistency/proposal.md)并同步到[主规格](../../openspec/specs/screenshot-io/spec.md)；依据根目录 `hylyre-0.5.2-截图文件编码与扩展名一致性修复需求.md`。证据根目录 `.hylyre/verification/0.5.2/` 被 gitignore，以下日志名均相对该目录。离线验证使用真实可解码图像，只替代采集/传输边界；设备证据单列。

## 根因、改动与错误行为

0.5.1 保留请求的 `.png` 路径，却直接写入 Hypium JPEG 字节；失败诊断同样将 JPEG 写入 `.png`。四处重复 MIME 判断将非 JPEG 默认当作 PNG，不能识别损坏图片。

- `hylyre/image_io.py` 统一后缀、PNG/JPEG verify → reopen/load 完整校验、真实 MIME、必要转码与同目录临时文件关闭后原子替换。
- `hylyre/cli/commands/loop_cmd.py` 在采集/设备连接/session IPC 前拒绝坏后缀，会话 MIME 由实际字节决定；`hylyre/api/failure_diag.py` 保存有效 PNG 后才登记附件。
- `hylyre/session/daemon.py`、`hylyre/mcp/server.py`、`hylyre/vlm/http_vlm.py` 使用同一完整校验，保留有效原字节、现有参数和响应形态。
- `pyproject.toml` 与 `hylyre/__init__.py` 同步0.5.2，声明 Pillow 核心依赖；CLI帮助、CHANGELOG、README同步说明。
- `tests/image_samples.py` 提供有空间图案的真实 JPEG/PNG、半透明样例和坏图；公共 FakeUiDriver 坏 CRC PNG、HTTP VLM 伪头成功素材及相关 Hypium 测试修正。新增图像单元和实际入口测试。

支持 `.png/.jpg/.jpeg`，大小写不敏感且保留请求路径；不支持或无后缀明确失败，不静默改名。同格式保留原字节，跨格式不缩放/裁剪；透明 PNG 经 RGBA 白底合成，JPEG quality=95。有效 CMYK JPEG 转 PNG 时先转 RGB。CLI ImportError exit2，其它截图异常 exit1，stderr给原因、失败stdout无成功路径。采集/校验/编码/写入/关闭/替换失败不发布半写目标、不破坏旧图、不登记成功截图附件。诊断失败保持原业务失败和成功UI dump；不承诺断电持久性。

## 补修：MPO 与发布文件权限

- **MPO**：Pillow 把带 MPF（多图）段的 JPEG 报为 `MPO`，此前被当作不支持格式拒绝，所有截图入口都会失败。现按 JPEG 处理：`image_mime` 返回 `image/jpeg`，存 `.jpg/.jpeg` 保留原字节，转 PNG 取首帧。
- **文件权限**：同目录临时文件在 POSIX 上是 0600，替换后最终截图与诊断 PNG 只有属主可读。现在替换前设为 `0666 & ~umask`，与 0.5.1 `write_bytes` 一致。umask 在模块导入时读取一次。
